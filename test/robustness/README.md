# vivlio-starter-pdf 堅牢性テスト

通常のユニットテストが「正しく使ったとき正しく動くか」を見るのに対し、ここは
**「壊れた PDF・壊れた項目・書けない環境に対してどう振る舞うか」** を見る。
本体（vivlio-starter）の `test/vivlio_starter/robustness/` と同じ位置づけ。

## ここで守る 2 つの約束

1. **公開 API は例外を外へ出さない。**
   このプロバイダはビルドパイプラインの途中から呼ばれる。1 つの PDF 操作が例外で
   飛ぶとビルド全体が落ちるため、失敗は戻り値で伝える
   （`page_count` は `nil`、`add_outline!` は `false`）。

2. **失敗しても入力を壊さない。**
   `add_outline!` は、読み込んだのと同じパスへ書き戻す。
   途中で失敗して元 PDF が切り詰められると「ビルドは続いたのに成果物が壊れている」
   という、最も気付きにくい失敗になる。

**「落ちないこと」だけを見ないこと。** とくにアウトラインは、壊れた見出しが 1 つ
あるだけで全滅すると読者がしおりを失う。`add_outline!` は `false` を返すだけで
PDF 自体は出来上がるので、**成果物を開くまで誰も気付けない**。
1 件ずつ飛ばして残りを書き、飛ばした理由を `on_skip` で報告することまで固定する。

## 実行方法

```sh
rake test                                          # 全テスト（堅牢性を含む）
ruby -Ilib -Itest test/robustness/<name>_test.rb   # 個別
```

## テスト一覧

| テストファイル | 検証内容 |
|:---|:---|
| `broken_pdf_test.rb` | PDF でないファイル・0 バイト・存在しないパス・暗号化 PDF・書き込み不可ファイル。いずれも例外を出さず、入力を書き換えない |
| `outline_entry_test.rb` | 壊れたアウトライン項目（不正 UTF-8 のタイトル・範囲外ページ・空タイトル・`nil` や想定外の型・深すぎる階層）を 1 件ずつ飛ばし、残りは書く。全滅時は空のしおりツリーを残さない |

## ガイドライン

1. **一時ディレクトリで完結させる**（`RobustnessHelper#in_workdir`）。
2. **環境依存は `skip` でフォールバック**。権限操作が効かない環境（root）では理由を明示して skip。
3. **HexaPDF のページボックスに凍結した配列を渡さない。** 破壊的に扱われるため
   `FrozenError` になる（`a4_box` が毎回新しい配列を返すのはこのため）。
4. **ログは伏せる**（`silently`）。堅牢性テストが見るのは戻り値と副作用であって、文言ではない。
